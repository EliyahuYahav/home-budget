# תקציב הבית

אפליקציה לניהול הוצאות, תקציב וחיסכון של הבית, לשני בני זוג. נפתחת בדפדפן וניתנת להתקנה על מסך הבית בטלפון (PWA).

## מה יש בגרסה הזו

- **בוט**: כותבים "סופר 230" או "דלק 180 אתמול", והוא רושם את ההוצאה ומשייך לקטגוריה. אפשר גם לשאול "כמה נשאר לנו החודש?".
- **בית**: כמה מותר להוציא היום, אחרי חיסכון וחשבונות קבועים.
- **הוצאות**: רשימה עם חיפוש וסינון, עריכה ומחיקה, הוספה ידנית והכנסות חד־פעמיות.
- **תקציב**: תקציב מול ביצוע לכל קטגוריה, עם התרעה מ־80%.
- **הגדרות**: הכנסות קבועות, קוד הזמנה לבן או בת הזוג.

## הקמה (פעם אחת)

1. **Supabase**: פותחים פרויקט חינמי ב־[supabase.com](https://supabase.com).
2. **סכמה**: ב־SQL Editor מדביקים ומריצים את כל הקובץ `supabase/schema.sql`.
3. **מפתחות**: מעתיקים את `.env.example` ל־`.env.local` וממלאים:
   - `NEXT_PUBLIC_SUPABASE_URL` ו־`NEXT_PUBLIC_SUPABASE_ANON_KEY` מתוך Project Settings → API.
   - `ANTHROPIC_API_KEY` (לא חובה): מפתח מ־[platform.claude.com](https://platform.claude.com). בלעדיו הבוט עובד עם זיהוי בסיסי מובנה.
4. **אישור מייל**: כברירת מחדל Supabase שולח מייל אישור בהרשמה. אפשר לכבות את זה ב־Authentication → Sign In / Providers → Email → Confirm email.

## הרצה

```bash
npm install
npm run dev
```

האתר עולה ב־http://localhost:3000. נרשמים, פותחים משק בית, ואת קוד ההזמנה ממסך ההגדרות נותנים לבן או בת הזוג.

## סנכרון מהבנק ומכרטיס האשראי

ההוצאות נקראות מאתר הבנק ומאתרי חברות האשראי עם פרטי הכניסה שלכם, ונרשמות באפליקציה. הקריאה עצמה נעשית על המחשב בבית, עם הספרייה [israeli-bank-scrapers](https://github.com/eshaham/israeli-bank-scrapers), כי האתר ב־Vercel לא יכול להפעיל דפדפן ובנקים חוסמים כניסות משרתים בענן. הרשימה כוללת את כל הבנקים וחברות האשראי שהספרייה תומכת בהם (הפועלים, לאומי, דיסקונט, מזרחי־טפחות, הבינלאומי, מרכנתיל, אוצר החייל, מסד, יהב, פאגי, מקס, כאל, ישראכרט, אמריקן אקספרס ועוד). רק דיסקונט ומקס נבדקו מול חשבון אמיתי; השאר רשומים עם שדות הכניסה שהספרייה מתעדת.

מהאתר מפעילים ורואים את הסנכרון דרך **אפשרויות מפתחים**: במסך ההגדרות לוחצים שבע פעמים על שורת הגרסה.

לפני שמתחילים, כדאי לדעת:

- פרטי הבנק שממלאים באתר מוצפנים בדפדפן עם מפתח ציבורי של המחשב בבית. במסד נשמר רק הטקסט המוצפן. המפתח שפותח אותו נמצא רק בקובץ `sync/agent-key.json` במחשב, ולא נכנס ל־git.
- כניסה אוטומטית עם הסיסמה בדרך כלל לא מותרת לפי תנאי השימוש של הבנק. ההחלטה להשתמש בזה היא שלכם.
- כשהבנק משנה את האתר שלו, הסנכרון עלול להפסיק לעבוד עד שהספרייה מתעדכנת (`npm update` בתיקיית `sync`).

הקמה, פעם אחת:

1. מריצים שוב את `supabase/schema.sql` ב־SQL Editor של Supabase. הוא מוסיף את העמודה שמונעת כפילויות ואת טבלאות הסנכרון.
2. מתקינים את הספרייה:
   ```bash
   cd sync
   npm install
   ```
3. מעתיקים את `sync/.env.example` ל־`sync/.env` וממלאים רק את `APP_EMAIL` ו־`APP_PASSWORD` (המייל והסיסמה של האפליקציה).
4. מפעילים את הסוכן ומשאירים את החלון פתוח:
   ```bash
   npm run agent
   ```
5. באתר, באפשרויות מפתחים: כשמופיע "מחובר", ממלאים את פרטי הבנק ומקס ושומרים, ואז לוחצים "ריצת ניסיון" ועוברים על הפלט. אם הוא נראה נכון, "סנכרון" רושם בפועל.

במסך אפשר לבחור כמה אחורה לקרוא (חודש עד שנה). הסנכרון היומי קורא חודש; טווח ארוך יותר מתאים לייבוא ראשון. באותו מסך יש גם "איפוס נתונים": מוחק את כל ההוצאות, ההכנסות והיסטוריית הבוט של משק הבית, אחרי הקלדת מילת אישור והורדת קובץ גיבוי, ומשאיר קטגוריות, תקציב, הגדרות ומשתמשים.

איך זה עובד: הכפתור באתר רושם בקשה במסד, הסוכן במחשב רואה אותה תוך כמה שניות, מריץ את הסנכרון ושולח את הפלט בחזרה. בקשה שנשלחה כשהמחשב היה כבוי פגה אחרי עשר דקות ולא תרוץ בהפתעה. אחרי שסנכרון אמיתי אחד הצליח, הסוכן מריץ סנכרון בעצמו כשעבר יום מהקודם (`AUTO_SYNC=off` ב־`sync/.env` מבטל את זה).

מה הסנכרון עושה עם כל תנועה:

- **הוצאה חדשה** נרשמת עם הסימון "מהבנק", ו־Claude משייך לה קטגוריה. מה שלא ברור נשאר בלי קטגוריה ומופיע בהתרעה במסך ההוצאות.
- **הוצאה שכבר רשמתם בבוט** (אותו סכום, עד יומיים הפרש) לא נרשמת שוב; היא רק מסומנת כדי שתזוהה בפעם הבאה.
- **כסף שנכנס לחשבון** נרשם כהכנסה. לכן לא מגדירים במקביל הכנסות קבועות במסך ההגדרות, אחרת המשכורת נספרת פעמיים. `IMPORT_INCOME=off` ב־`sync/.env` מחזיר לקריאת הוצאות בלבד.
- **משיכה מכספומט** משויכת לקטגוריה ששמה כולל "מזומן", אם יש כזו. המזומן נספר כהוצאה כשהוא נמשך. קנייה שנרשמת כ"שולם במזומן" (בבוט: "ירקות במזומן 80", או בתיבת הסימון במסך ההוצאות) יורדת ממשיכות המזומן של אותו חודש ונספרת בקטגוריה שלה, כך שהכסף לא נספר פעמיים.
- **לא נרשמים**: חיובים שעוד לא סופיים, העברה בין שני חשבונות שלכם (יוצאת מאחד ונכנסת לשני באותו סכום), והחיוב החודשי בחשבון הבנק של כרטיס שהסנכרון קורא, כי ההוצאות שבו כבר נקראות אחת־אחת מהכרטיס. הפלט מפרט כל שורה שדולגה.

כדי שהסוכן יעלה לבד בכל כניסה למחשב, פעם אחת בשורת הפקודה של Windows (cmd, לא PowerShell). מתקנים את הנתיב אם הפרויקט נמצא במקום אחר:

```bat
schtasks /Create /TN HomeBudgetAgent /SC ONLOGON /TR "\"D:\self projects\home-budget\sync\start-agent.cmd\""
```

מה שהסוכן עשה נכתב אז ל־`sync/agent.log`.

אפשר גם בלי האתר: ממלאים את פרטי הבנק ב־`sync/.env` ומריצים `npm run dry-run` או `npm run sync`. אם הבנק מבקש קוד ב־SMS, `node bank-sync.mjs --show-browser` פותח חלון שאפשר להקליד בו; דרך האתר אין לזה תמיכה.

## שימוש על ידי כמה משפחות

האתר בנוי כך שכמה משקי בית משתמשים בו בלי לראות זה את זה: כל שורה במסד שייכת למשק בית, וההרשאות במסד עצמו חוסמות גישה ממשק בית אחר (`npm run test:db` בודק את זה).

מה צריך כדי לצרף משפחה:

1. **לפתוח הרשמה** ב־Supabase (Authentication → Sign In / Providers → Allow new users to sign up), לכמה דקות או לתמיד. המשפחה נרשמת באתר ופותחת משק בית משלה; בן או בת הזוג מצטרפים עם קוד ההזמנה.
2. **מפתח Claude משלהם**: בהגדרות, תחת "הבוט ו־Claude", מדביקים מפתח מ־platform.claude.com. המפתח נבדק מול Anthropic ונשמר מוצפן; השימוש מחויב בחשבון שלהם. בלי מפתח הבוט עובד בזיהוי בסיסי.
3. **סנכרון מהבנק** (לא חובה): כל משפחה מריצה את הסוכן על המחשב שלה, עם הפרטים שלה. ראו "סנכרון מהבנק ומכרטיס האשראי". פרטי הבנק שלה נפתחים רק במחשב שלה.

מה מי שמפעיל את האתר צריך להגדיר פעם אחת:

- משתנה הסביבה `SECRETS_KEY` ב־Vercel (ראו `.env.example`). בלעדיו אי אפשר לשמור מפתחות Claude של משפחות.
- להחליט אם להשאיר את `ANTHROPIC_API_KEY` ב־Vercel. כשהוא מוגדר, משפחה בלי מפתח משלה משתמשת בו, עד 150 הודעות ביום. כדי שכל משפחה תשלם על עצמה, שומרים את המפתח של הבית שלכם בהגדרות כמו כולם ומוחקים את המשתנה.

מה חשוב שהמשפחות יידעו:

- **מי שמנהל את פרויקט ה־Supabase יכול לראות את כל ההוצאות וההכנסות של כל המשפחות.** ההרשאות מגינות על משפחה מפני משפחה אחרת, לא מפני מנהל המסד. מי שמצטרף סומך על המפעיל.
- מפתח ה־Claude שלהם נשמר מוצפן, אבל מי שמפעיל את האתר מחזיק את מפתח ההצפנה ויכול טכנית לפתוח אותו. תקרת הוצאה בחשבון ה־Anthropic שלהם מגבילה את הנזק האפשרי.
- פרטי הכניסה לבנק מוצפנים למחשב שלהם בלבד, וגם המפעיל לא יכול לקרוא אותם.
- משק בית מוגבל לשני חברים.

## אבטחה

מה מגן על הנתונים:

- **הרשאות במסד (RLS)**: כל שורה שייכת למשק בית, ורק חברים בו רואים או משנים אותה. מי שלא מחובר לא מקבל גישה לשום טבלה. `npm run test:db` מריץ את `supabase/schema.sql` על Postgres בזיכרון ומנסה 42 פעולות, ביניהן קריאה וכתיבה בלי התחברות, גישה למשק בית אחר, והחלפת קוד ההזמנה.
- **משק בית נסגר בשני חברים**: אחרי ששני בני הזוג הצטרפו, קוד ההזמנה כבר לא מכניס אף אחד.
- **המפתח שבדפדפן הוא ציבורי בכוונה** (`NEXT_PUBLIC_SUPABASE_ANON_KEY`): הוא לא נותן גישה לנתונים בלי התחברות. מפתח `service_role` לא נמצא בשימוש בשום מקום בפרויקט. מפתח Claude נמצא רק בשרת.
- **פרטי הבנק** מוצפנים בדפדפן למפתח של המחשב בבית, ולא נכתבים לפלט הסנכרון גם אם הבנק מחזיר אותם בהודעת שגיאה. לפני מילוי משווים את קוד המפתח שבמסך לזה שהסוכן מדפיס.
- **הבוט**: משק בית עם מפתח Claude משלו משלם על עצמו. על המפתח של האתר, עד 150 הודעות ביממה למשק בית עוברות ל־Claude; מעבר לזה עונה הזיהוי המובנה, כך שאי אפשר לנפח את החשבון.
- **כותרות אבטחה** בכל תשובה של האתר: איסור הטמעה באתר אחר, HSTS ועוד (`next.config.ts`).

מה צריך להגדיר ידנית, כי זה לא בקוד:

1. **לסגור הרשמה** אחרי ששניכם רשומים: ב־Supabase, Authentication → Sign In / Providers → לכבות "Allow new users to sign up". כל עוד ההרשמה פתוחה, כל אחד יכול לפתוח חשבון ומשק בית משלו (בלי לראות את שלכם) ולהשתמש בבוט על חשבונכם.
2. **אימות דו־שלבי** בחשבונות Supabase, Vercel, GitHub ו־Anthropic. מי ששולט באחד מהם יכול לשנות את האתר או לקרוא את המסד.
3. **תקרת הוצאה** בחשבון Anthropic (Billing → Limits).
4. **המחשב בבית**: `sync/.env` מכיל את סיסמת האפליקציה, ו־`sync/agent-key.json` פותח את פרטי הבנק. מי שיש לו גישה למחשב יכול לקרוא אותם, ולכן כדאי משתמש Windows עם סיסמה והצפנת דיסק (BitLocker).

ידוע ולא מטופל: `npm audit` בתיקיית `sync` מדווח על חולשות בכלי הורדת הדפדפן של puppeteer (`extract-zip`, `basic-ftp`). הסנכרון משתמש ב־Chrome המותקן ולא מוריד דפדפן, כך שהקוד הזה לא רץ; התיקון המוצע הוא שנמוך לגרסה ישנה של הספרייה.

## מבנה

| נתיב | תפקיד |
| --- | --- |
| `supabase/schema.sql` | טבלאות, הרשאות (RLS) ויצירת משק בית עם קטגוריות התחלתיות |
| `src/lib/budget.ts` | חישובי החודש: חיסכון קודם, חשבונות קבועים, "מותר להוציא היום" |
| `src/lib/bot.ts` | פענוח הודעה בעזרת Claude, עם נפילה לזיהוי המובנה |
| `src/lib/parse-fallback.ts` | הזיהוי המובנה, בלי שירות חיצוני |
| `src/app/actions.ts` | כל הפעולות בשרת: התחברות, הוצאות, תקציב, בוט |
| `src/app/(app)/` | המסכים: בית, בוט, הוצאות, תקציב, מגמות, הגדרות |
| `sync/` | סנכרון מהבנק ומכרטיס האשראי, רץ על המחשב בבית ולא באתר |

## איך מחושב "מותר להוציא היום"

```
הכנסות החודש (קבועות + חד־פעמיות)
− חיסכון (היעד החודשי, או מה שהופרש בפועל אם הוא גבוה יותר)
− מה שכבר הוצא
− חשבונות קבועים שעוד לא שולמו
= הסכום הפנוי, שמתחלק על הימים שנשארו בחודש
```
